Executive Summary

From on-chain complexity to confident action

The challenge wasn't aesthetic — it was structural. EigenLayer introduced restaking to Ethereum's financial stack, and the ecosystem grew faster than tooling could follow. Users managing positions across operators, AVSs, LSTs, and LRTs were piecing together a picture from raw contract data, Discord threads, and spreadsheets. No single interface unified the system.

Restaking.Info addresses that directly. It aggregates the full restaking stack — TVL overview, AVS status, 364 operators, LST and LRT distribution, permissionless tokens, rewards, and on-chain events — into nine linked views built around one principle: every screen should move the user one step closer to a decision, not deeper into data.

The simplification problem

EigenLayer's architecture is complex. The product design had to be simple.

AVSs, operators, LSTs, LRTs, slashing conditions, reward mechanisms, permissionless tokens — surfacing all of it is the wrong answer. The right answer was to identify the three questions every user is actually trying to answer:

01

Is my capital safe?

Operator health, slashing risk, AVS exposure — risk state surfaces first, everywhere.

02

Am I earning what I should?

Rewards accrued, APR trends, TVL trajectory — yield clarity without contract parsing.

03

Should I change anything?

Comparative operator data, upgrade readiness, client diversity — everything needed to act with confidence.

The nine platform views map to these three questions — not to EigenLayer's technical architecture.

Business model

01

API as a service

All restaking data — TVL, operator metrics, AVS status, LST distribution — exposed through a paid API. Protocols, dashboards, and developers pay for programmatic access to clean, normalised on-chain data without having to index it themselves.

02

Operator promotion

Operators — starting with Nethermind's own — can pay to be featured and promoted within the dashboard. The platform turns its own analytics into a distribution channel for the operator business, creating a direct commercial loop between the product and Nethermind's restaking infrastructure.

03

Support plan

A $1.99/month subscription that removes promotions from the interface — a lightweight way to monetise power users who want a clean, ad-free experience while keeping the core product free.

How it works

01

Connect your wallet

Link any EVM wallet. The dashboard instantly reads all restaking positions across supported protocols — no manual input required.

02

See your full picture

Total restaked value, rewards accrued, operator health scores, and slashing risk — all in one view, updated in real time.

03

Act with confidence

Restake, withdraw, or switch operators directly from the dashboard. Smart alerts surface critical changes before they become costly.

Design principles

01

Clarity over completeness

Surface the 20% of data that drives 80% of decisions. Hide the rest behind progressive disclosure.

02

Trust through transparency

Every number is attributable. Users can always drill down to the on-chain source.

03

Protocol-agnostic

EigenLayer, Symbiotic, Karak — the DS is built to extend to any new protocol without a redesign.

04

Action-oriented

Analytics without action is noise. Every insight leads to a clear next step the user can take.

Designing for decisions, not just data

The hardest UX problem in restaking is operator selection — users are committing staked ETH to an operator they can't easily evaluate, a decision with real slashing risk and real yield implications. The operator flow was designed as a decision funnel, not a data dump: List → Filter → Profile → AVS Exposure. Each step reduces uncertainty before commitment. The list surfaces the metrics that matter (TVL, number of AVSs, ETH managed). The filter narrows by what the user cares about. The profile gives the full picture. The AVS sub-tab shows exactly what the operator is opted into — the last question before a user acts.

Owned entirely in Figma — from component architecture to interactive flows. Every section covers the full state space: AVS detail maps three sub-views (Total Value, Operators, Re-stakers); the Operator flow covers list, search match, empty state, 404, operator detail, and the AVS-Operators tab.

Design System

The engine behind the product

A DeFi dashboard is only as trustworthy as it looks. Every component was built to communicate precision — tight spacing, monospaced numbers, semantic colour for risk states.

Typography

Inter for UI labels and body. Monospaced numerals throughout — every number right-aligns and scales identically regardless of digit count.

Colour & Risk

A strict semantic palette: green for healthy, amber for caution, red for risk. No decorative use of colour — every hue carries meaning the user can rely on.

Components

Position card, operator health badge, reward ticker, risk meter, wallet connect flow — a component set covering every interaction pattern in the dashboard.

Scalability

Each component is protocol-agnostic by design. Adding Symbiotic or Karak support requires no new UI patterns — just new data piped into existing components.

What I'd do with more time

01

Mobile companion app

The dashboard is inherently desktop-first, but critical alerts (slashing risk, reward milestones) need to reach users on mobile. A lightweight iOS/Android companion is the clearest next surface.

02

Multi-wallet aggregation

Power users often manage restaking across 3–5 wallets. A portfolio aggregation view — treating multiple wallets as one entity — is a high-value feature with clear technical complexity worth solving.
